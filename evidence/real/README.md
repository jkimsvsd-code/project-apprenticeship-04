# 실제 두 KST 날짜의 앱 기록 대조

후속 확인: 로그인한 공식 T04의 과정 기록도 0건이며 영수증 payload 대조는 미실시입니다. 현재 웹은 과정 기록을 선택 사항으로 안내하고 카드 C22~C24 문구도 보관된 공개 계약과 다릅니다. [공식 화면 확인 자료](official-receipt-check.json)와 [기준 차이 설명](../../docs/official-receipt-check.md)을 참고하세요. 아래 영수증 조건은 확보한 공개 계약 기준이며 제출·승인 차단 사유를 뜻하지 않습니다.

2026-10-27 KST에 이미 저장된 운영 기록을 읽기 전용으로 확인했습니다. 새 원천 조회나 DB 쓰기는 수행하지 않았습니다.

| 날짜 · KST | 실제 조회 · KST | 원천 기준 · KST | 값 |
| --- | --- | --- | --- |
| 2026-10-26 | 21:11:07.872 | 21:00:00 | 14.6°C |
| 2026-10-27 | 00:46:49.214 | 00:45:00 | 12.8°C |

원자료 → 정규화 저장값 → 일별 대표값 → 고정 보관본 → 화면값이 일치합니다. 원천 Unix 시각의 UTC ISO 변환과 fetched_at의 KST 날짜도 대조했습니다. 변화량은 **12.8 − 14.6 = −1.8°C**, 화면의 방향은 감소·크기는 1.8°C·날짜 간격은 1일입니다. 서로 다른 달력 날짜의 조회이며 48시간 연속 관찰이나 일평균 기온을 뜻하지 않습니다.

사용자는 2026-10-27 이 대화에서 **값만 기록했으며 공식 영수증은 아직 없다**고 확인했습니다. 영수증은 0건이며 이 자료는 앱이 만든 봉인 영수증이 아닙니다. 플랫폼의 공식 발급 절차, 정확히 두 `t04_day` 영수증의 `server_created_at` KST 날짜와 payload 대조는 남아 있습니다. 과거 조회·보관 시각을 영수증 발급 시각으로 대신하지 않습니다. 따라서 7B 전체·C22~C24·최종 제출 완료로 판정하지 않습니다.

일별 대표값은 나중 조회에서 바뀔 수 있지만 선택한 UUID 보관본 링크의 값은 유지됩니다. 기존 `evidence/implementation/`의 한 날짜 검증 자료는 당시의 사실이므로 수정하지 않습니다.
