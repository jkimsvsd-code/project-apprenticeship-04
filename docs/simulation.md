# 합성 실패·복구 재생

[공개 재생 패널](https://project-apprenticeship-04.vercel.app/#simulation)에서 로그인 없이 확인합니다. 아래 값과 2026년 8월 날짜는 공식 합성 시험값이며 실제 서울 기온·실제 이틀 조회·플랫폼 영수증을 대체하지 않습니다.

## 기본 확인 순서

1. **정상 기준값 105 준비**: 빈 합성 상태에서 D1-A 100 → D1-B 105를 처리합니다. 같은 KST 날짜이므로 기록 한 건과 record ID가 유지됩니다.
2. 실패 한 종류를 선택합니다. 105pt·1건이 보존되고 `stale`과 해당 오류 코드가 표시됩니다. 실패마다 이유와 다음 행동이 다릅니다.
3. **다시 시도 · 합성 D2 복구**: 지정된 RECOVER-D2를 처리합니다. 120pt·2건·`fresh / none`으로 복구되고 새로운 날짜 기록이 한 건 생깁니다. 이미 D2가 있으면 같은 ID로 갱신하여 중복 행을 만들지 않습니다.

실패를 바꿀 때마다 기준값 준비부터 반복하면 독립적으로 비교할 수 있습니다. **합성 기록 초기화**는 현재 창의 합성 값·행·오류·비교·실행 이력을 비웁니다. 정상값 없이 바로 실패를 누르면 값 없음·0건을 유지합니다. 정상값 없이 지정 복구를 실행하면 D2 한 건만 생깁니다.

## 공식 입력 매핑

| 화면 조작 | fixture ID | 실제 판정 |
| --- | --- | --- |
| 정상 D1-A · 100 | T04-NORMAL-D1-A | 100pt, 첫 날짜 한 건 |
| 동일 날짜 D1-B · 105 | T04-NORMAL-D1-B | 105pt, 기존 ID 갱신 |
| 다음 날짜 D2 · 120 | T04-NORMAL-D2 | 120pt, 다음 날짜 한 건 추가 |
| 느린 응답 | T04-TIMEOUT | timeout |
| 원천 401 거절 | T04-AUTH-401 | auth; 제공자 거절이며 방문자 로그인 요구 없음 |
| 호출 제한 | T04-RATE-429 | rate_limit; Retry-After 60초 |
| 오프라인 | T04-OFFLINE | offline |
| 형식 변경 | T04-SCHEMA-BREAK | schema_error |
| 다시 시도 · 합성 D2 복구 | T04-RECOVER-D2 | fresh / none |

원본 ID·시각·전송 정보·payload는 [공식 자산](../public/task-assets/t04/)을 수정하지 않고 가져옵니다. 공개 계약은 2.0.0, fixture 계약은 1.1.0입니다. 재생 엔진은 `expected`를 답으로 읽지 않고 전송 상태와 payload를 공통 규칙으로 처리합니다.

## 대기·시각·상태 확인

느린 응답의 지연/제한과 호출 제한의 Retry-After는 공식 입력의 합성 메타데이터입니다. 복구 버튼은 실제 60초를 기다리는 타이머가 아니라 공식 가상 D2로 이동하는 시험입니다. 원천 호출 없이 즉시 처리하며 실제 대기 UX 검증을 대신하지 않습니다.

**정상 D1/D2를 순서대로 재생**에서 날짜별 성공을 직접 확인할 수 있습니다. **판정 상태와 합성 일별 기록 확인**에서는 freshness·error_code·fixture·가상 시각·지연/제한·날짜별 값·record ID와 전체 상태 JSON을 확인합니다. D1-B 105 → D2 120은 `increase`, 크기 15pt입니다. 동일한 비교 컴포넌트를 실제 기록에도 사용하며, 현재 한 날짜뿐인 실제 기록은 비교 부족을 안내합니다. 합성 비교 카드에서는 두 저장값·단위·날짜·계산식을 펼쳐 볼 수 있습니다.

## 실제 기록과 격리

합성 상태는 React의 현재 창 메모리에만 있으며 페이지를 새로고침하거나 새 창을 열면 초기화됩니다. 재생·초기화·복구는 `/api/board`, 외부 원천, DB를 호출하지 않습니다. 서버 저장소·실제 날짜·실제 시계를 수정하지 않습니다. 합성 값은 실제 정보판 위쪽에 표시되지 않습니다.

검증 결과는 [5단계 보고서](../evidence/implementation/stage5.json), [실제 브라우저 상태](../evidence/synthetic/stage5-browser-replays.json)에 있습니다. 참조 adapter와 앱 엔진은 정상·실패 5종·복구의 전체 상태가 일치하며, expected 변조·세션 격리·초기화·중복 복구도 단위 시험으로 확인했습니다.
