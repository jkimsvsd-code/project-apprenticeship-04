# 영수증 대조용 고정 보관본

실제 기온 조회가 성공하면 일별 대표값과 함께 별도의 고정 보관본을 같은 DB transaction에 저장합니다. 같은 날짜의 대표값은 한 줄로 갱신되지만, 이미 생성한 보관본의 값·원자료·시각·고유 링크는 유지됩니다.

## 2026-10-27 확인 결과

2026-10-26 21:11:07 KST의 **14.6°C**와 2026-10-27 00:46:49 KST의 **12.8°C**가 실제 운영에 보관되어 있습니다. [두 고정 기록 비교](https://project-apprenticeship-04.vercel.app/review/6f2d9580-3c2f-478a-bdda-814d5030c4c9?compare=ea6a373d-4983-4115-90d7-2faaec9399f7)의 **1.8°C 감소**와 원자료·저장값·화면값이 일치합니다. [검증 증거](../evidence/real/two-day-verification.json)를 보관했습니다. 공식 영수증은 사용자 확인 기준 아직 발급받지 않았습니다.

## 직접 이틀을 확인하는 순서

1. [정보판](https://project-apprenticeship-04.vercel.app/#main-reading)에서 기온을 새로 조회하고 **이 값의 고정 기록 보기**를 엽니다.
2. 열린 `/review/…` 주소를 개인 기록에 보관합니다. 플랫폼 영수증을 작성·대조할 때 이 페이지의 **영수증 대조 항목**을 사용합니다. 해당 페이지를 새로고침해도 값을 다시 조회하지 않습니다.
3. 다른 실제 KST 날짜에 같은 순서를 반복하여 두 번째 보관본 주소를 보관합니다.
4. 첫 번째 고정 기록에서 **비교할 다른 날짜의 고정 기록 주소**에 두 번째 링크를 넣고 **두 고정 기록 비교**를 누릅니다. 비교 페이지의 주소에는 두 보관본이 고정되므로 이후 재조회에도 비교 대상이 바뀌지 않습니다.

같은 KST 날짜의 보관본 두 개는 실제 이틀이 아닙니다. 화면에서 같은 날짜임을 별도로 안내하고 이틀 변화량을 만들지 않습니다. 같은 원천·단위의 서로 다른 두 날짜가 있으면 실제 날짜와 간격·값·방향·크기·계산 상세를 표시합니다. 영수증의 `server_created_at` 순서와 두 날짜 일치 여부는 실제 공식 영수증을 확보한 뒤 별도로 대조합니다.

**고정 보관본은 플랫폼 영수증이 아닙니다.** 앱이 발급·서명하거나 영수증 개수를 늘리지 않습니다. 앱의 두 실제 날짜 값 대조는 완료했지만, 실제 발급 절차·공식 영수증 진위·payload 일치·server_created_at의 서로 다른 KST 날짜 여부는 아직 확인 전입니다. 현재 화면의 영수증 미연결 표시는 유효합니다.

## 대조할 필드와 시각

| 플랫폼 항목 | 보관본의 값 |
| --- | --- |
| source_url | 실제 요청한 고정 공개 원천 URL |
| source_observed_at | reading.source_time; 원천 기준 시각을 UTC ISO로 표시 |
| normalized_value | 조회 당시 검증·저장한 기온 값 |
| unit | °C |

실제 조회 시각은 `fetched_at`, 앱에 보관본을 만든 시각은 `created_at`입니다. 둘 다 원천 기준 시각이나 플랫폼의 `server_created_at`을 대신하지 않습니다. 한 페이지에서 원자료와 정규화 저장값도 펼쳐 확인할 수 있습니다.

## 저장과 공개 접근

- 보관본은 Neon Postgres에 영속 저장합니다. 브라우저 저장소나 배포 임시 파일에 의존하지 않습니다.
- 보관본 식별자는 UUID이며 링크는 해당 원천의 보관본만 읽습니다. URL이나 비교 입력이 임의 원천을 호출하거나 값을 쓰지 않습니다.
- 보관본 저장은 서버가 검증한 실제 조회 성공 경로에서만 수행합니다. 공개 API는 값·날짜·원천 URL을 입력받지 않습니다.
- `(signal_id, fetched_at)` 고유 제약으로 동일 성공값의 중복 보관을 막습니다. 실패·오래된 시도는 보관본을 만들지 않습니다.
- 런타임 역할은 review_snapshots에 SELECT/INSERT만 갖고 UPDATE/DELETE는 거절됩니다. DB 관리자의 유지보수 권한까지 제거한 봉인 저장소라고 주장하지 않습니다.
- 일별 대표값·보관본·정상 상태 변경을 하나의 transaction으로 저장합니다. 보관본 저장이 실패한 조회를 정상 저장 완료로 표시하지 않습니다.
- migration 002는 기존 일별 저장값을 당시 원자료·조회 시각 그대로 한 번 보관합니다. migration 시각을 과거 조회 시각으로 꾸미지 않습니다. 이후 성공부터 조회별 보관본이 추가됩니다.
- 홈페이지는 최근 20건만 보여 주며, 더 오래된 고유 링크도 계속 읽을 수 있습니다. 비교할 보관본은 날짜·시각·값을 확인해 선택합니다.
- 합성 패널의 초기화·실패·복구는 실제 보관본을 만들거나 지우지 않습니다.

이 변경으로 고정값 보관과 공개 표시·비교 경로는 준비됐습니다. 공식 영수증 2건을 확보한 뒤 선택한 링크 두 개의 값·시각·단위와 대조해야 7B 실제 검증을 완료할 수 있습니다.
