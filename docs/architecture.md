# 구현 구조와 데이터 원칙

원천은 [Open-Meteo의 서울 고정 지점 기온](data-source.md), 공통 데이터·재생 계약은 [공개 계약 v2](task-contract.md)입니다. 기술은 Next.js App Router·TypeScript·Node.js 24, 공유 저장소는 Neon Postgres, 배포는 Vercel입니다. 5단계까지 서비스 연결·기본 조회·저장·화면·공식 합성 재생을 구현했습니다. [저장 모델](stack-and-storage.md), [연결 상태](setup.md)를 함께 확인합니다. 실제 변화량 UI·남은 UX·영수증 검증은 후속 단계입니다.

## 모듈 책임

| 위치 | 책임 |
| --- | --- |
| src/app | Next.js 화면·Route Handler 진입점; 업무 규칙은 기존 모듈에 위임 |
| src/board | 최신 값·출처·두 시각·오래된 값·오류 안내·재시도·첫 방문 UI |
| src/history | 일별 기록 표시, 비교 가능 여부 판단, 변화량과 계산 근거 |
| src/simulation | 공식 합성 입력 재생, 시험 초기화·상태 표시, 실제 저장소와 격리 |
| src/shared | 정규화 모델, 원천 응답 검증, KST 날짜·시각 계산, 공통 상태 규칙 |
| src/server | 공개 원천 조회, 실제 기록 영속 저장, 데이터 읽기·쓰기 경로 |

작은 프로젝트에 맞게 모듈을 유지하며, 단일 책임 파일이 필요할 때만 하위 폴더를 만듭니다. 화면에서 원천 호출·날짜 계산·저장을 직접 수행하지 않습니다.

## 실제 조회 흐름

사용자 새로고침 → 서버 조회 → 응답 구조·값·단위·시각 검증 → 정규화 → 일별 기록 및 마지막 정상값 저장 → 화면 표시.

- 가능한 경우 비밀키가 필요 없는 공개 원천을 우선 검토합니다.
- 키가 필요하면 서버 환경변수에서만 읽으며 브라우저로 전달하지 않습니다.
- 원천의 401/403은 데이터 제공자의 거절입니다. 공개 심사 사용자에게 로그인을 요구하지 않습니다.
- 응답 오류와 저장 오류를 구분합니다. 저장 실패를 정상 기록 완료로 표시하지 않습니다.
- 공개 방문자의 임의 값·날짜 입력을 실제 증거 저장소에 쓰지 않습니다.

## 기록 모델과 날짜

공통 정규화 항목은 `signal_id`, `normalized_value`, `unit`, `source_name`, `source_url`, `source_time`, `fetched_at`, `record_timezone`, `record_date`입니다. [공식 schema](../public/task-assets/t04/normalized-reading.schema.json)에 맞추고 대조에 필요한 비개인 원자료는 별도 저장합니다. 플랫폼 영수증의 `source_observed_at`은 정규화 모델의 `source_time`에 대응합니다.

- 일별 고유키는 원천 식별자와 `Asia/Seoul` 기준 조회 날짜로 만듭니다.
- 일별 대표값은 해당 날짜의 마지막 성공값을 채택하는 방향으로 설계합니다. 동시 요청에서는 더 오래된 성공 응답이 최신 기록을 덮어쓰지 않게 합니다.
- KST 조회 날짜와 원천 관측 날짜는 별개입니다. 관측 시각을 조회 시각으로 대체하지 않습니다.
- 날짜 키는 실제 서버 시각으로 만들며 공개 요청에서 임의 날짜를 주입하지 못하게 합니다.
- 일별 기록은 영속 저장합니다. 배포 런타임의 임시 파일이나 방문자별 브라우저 저장소만을 실제 증거의 유일한 저장소로 쓰지 않습니다.
- 실패가 기존 정상값·일별 기록을 지우거나 새 정상 기록을 만들면 안 됩니다.

## 상태와 오류

UI는 초기 데이터 없음, 조회 중, 정상, 마지막 정상값이 있는 실패, 마지막 정상값도 없는 실패를 구분합니다. 공식 저장 상태는 `fresh / none` 또는 `stale / timeout|auth|rate_limit|offline|schema_error`를 사용하며 초기 상태는 `null`입니다. 조회 중 표시는 이 저장 상태와 별도로 관리합니다.

실패 분류는 느림/시간초과, 원천 401/403, 호출 제한, 오프라인, 응답 형식 변경입니다. 실제 조회와 합성 재생은 `shared/reading.ts`의 9개 필드 정규화 검증, `shared/failures.ts`의 전송 오류 분류·Retry-After 해석·안내 문구를 공유합니다. 형식 검증이 끝나기 전에는 정상값을 갱신하지 않습니다.

마지막 정상값에는 마지막 성공 시각과 경과 시간을 표시합니다. 느린 요청은 유한한 제한 시간을 두고, 자동 재시도 반복은 현재 범위에 포함하지 않습니다. 대기 시간이 원천 제공값인지 앱의 안내값인지 구분합니다.

## 변화량

기본 변화량은 같은 원천·단위의 `나중 날짜 저장값 - 이전 날짜 저장값`입니다. 공식 참조 모델은 방향(`increase/decrease/unchanged`)과 절대 크기(`magnitude`, `last_delta`)를 분리합니다. UI는 증가/감소와 °C를 함께 표시하고 계산 상세에서 두 날짜·저장값을 보여줍니다.

전날 기록이 없으면 '어제 대비'로 오인하게 표시하지 않습니다. 비교 대상 날짜를 명시하고, 두 기록이 없거나 단위가 다르면 비교 불가 사유를 표시합니다. 비율 표시는 필수 범위가 아니며 분모가 0인 계산을 임의로 표시하지 않습니다.

## 합성 재생 격리

- [합성 재생 패널](simulation.md)은 React `useReducer`로 현재 창의 메모리에서만 동작합니다. 새로고침·새 창은 빈 합성 상태에서 시작하며 쿠키·공유 전역 상태·localStorage를 쓰지 않습니다.
- 재생 엔진은 `fetch`·API·서버 모듈·DB를 참조하지 않습니다. 공식 fixture의 전송 정보와 payload를 실제로 분류·검증하고 `expected`는 사용하지 않습니다.
- 실제 모드와 합성 시험 모드에 눈에 띄는 표시를 둡니다.
- 공개 심사 패널은 합성 입력만 받으며 공식 fixture를 임의로 변경하지 않습니다.
- 각 방문자의 합성 상태는 독립적이어야 합니다. 초기화는 합성 상태에만 적용합니다.
- 정상 D1-A → D1-B, 실패 5종, 지정 recover-d2를 공식 계약에 따라 재생합니다.
- 복구 후 `fresh`, `error_code: none`, 다음 날짜 기록 한 건 추가를 확인합니다.
- 실제 기록과 합성 상태에 저장 로직을 재사용할 수 있으나, 저장 인스턴스와 데이터 영역은 분리합니다.

## 아직 확정하지 않은 사항

프로젝트 라이선스와 플랫폼 t04_day 영수증 발급 절차는 아직 확정하지 않았습니다. 배포 환경의 최종 공개 접근 검증은 7단계입니다. 원천 사전 조회나 개발 DB 검증을 실제 이틀 검증 완료나 플랫폼 영수증으로 표시하지 않습니다.
