# 요구사항과 승인 범위

기준 자료: 사용자가 제공한 과제 4 PDF 5쪽과 2026-10-26 확보한 공식 공개 계약 v2.0.0. 공식 registry에는 T04-C01~C35의 35개 조건이 있습니다. [계약 대조](task-contract.md)를 함께 확인합니다. 로그인 뒤 과제 웹 화면의 최신 본문 자체는 아직 대조하지 못했습니다.

## 필수 요구사항

| 번호 | 요구사항 | 공개 계약 통과 기준 |
| --- | --- | --- |
| R1 | 비개인 공개 원천의 실제 동적 값 하나 조회 | T04-C03 |
| R2 | 값·단위·출처·관측 시각·조회 시각·기준 시간대 표시, 원자료·저장값·화면값 대조 | T04-C04~C10 |
| R3 | 느림·원천 401/403·호출 제한·오프라인·형식 변경을 합성 재생 | T04-C12~C16, C26 |
| R4 | 마지막 정상값 보존, 오래된 값 표시, 재시도 및 지정 fixture 복구 | T04-C17~C19 |
| R5 | 같은 KST 날짜 성공은 한 건으로 합치고 다음 날짜는 새 기록 | T04-C20~C21 |
| R6 | 다른 실제 KST 날짜의 봉인된 t04_day 영수증 정확히 2건, 저장값·화면값·변화량 대조 | T04-C22~C24 |
| R7 | 결과물·소스의 무인증 공개, 비밀키·실제 개인정보·개인 기록 노출 0건 | T04-C01~C02, C11, C25, C29~C33 |
| R8 | 공식 자산 ID·해시 및 시험 근거, 확인법 4줄, 판단 3줄, HTTPS 결과물 URL 및 커밋 고정 소스 URL | 카드 3 증거 기준, T04-C27~C28, C34~C35 |

PDF에서 생략된 C02와 C29~C35는 공식 registry에서 확인했습니다. 공개 접근 조건의 세분화 및 제출 URL 검증이며, 승인된 R7·R8의 검증 항목에 반영합니다. U8·U9의 현재 범위는 바꾸지 않습니다.

## 승인된 UX 기능

| ID | 기능 | 완료 판단 |
| --- | --- | --- |
| U1 | 첫 방문·기록 부족 안내 | 조회 전·첫 성공 후·이틀 기록 확보 상태에서 다음 행동을 알 수 있음 |
| U2 | 마지막 성공 경과 시간 | 절대 시각과 경과 시간을 함께 표시하고 상태를 색상·문구·아이콘으로 전달 |
| U3 | 요청 진행·중복 클릭 방지 | 진행 중임을 표시하고 같은 화면에서 중복 요청을 막음 |
| U4 | 재시도 대기 안내 | 원천이 제공한 대기 시간을 반영하고, 미제공 시 이를 구분해 안내 |
| U5 | 변화량 계산 상세 | 비교 날짜·두 저장값·단위·계산식을 펼쳐 볼 수 있음 |
| U6 | 모바일·키보드 접근성 | 좁은 화면에서 주요 정보가 읽히고 키보드 조작·초점·상태 안내가 동작 |
| U7 | 공개 심사용 합성 재생 패널 | 정상·실패 5종·복구를 재생하고 상태·기록 건수 변화를 확인 |

## 현재 범위 밖

- U8 검증 결과 복사·다운로드: 미승인. 구현 대상에서 제외합니다.
- U9 자동 갱신·장기 추이 차트: 후속 확장으로 승인되었습니다. 현재 버전에는 포함하지 않습니다.
- 다중 데이터 원천·사용자 계정·개인화·알림: 별도 요청 전에는 추가하지 않습니다.

## 완료 조건

앱 구현 완료와 과제 검증 완료를 구분합니다. 합성 시험이 통과해도 플랫폼의 canonical kind가 `t04_day`인 봉인 영수증 정확히 2건과 앱 저장값·화면값의 대조가 없으면 과제 검증은 미완료입니다. 날짜는 각 영수증의 `server_created_at`을 KST로 변환해 판정합니다. 기다린 시간은 과제의 계획 작업시간 6~7시간과 별개입니다. 앱이나 스크립트가 플랫폼 영수증을 자체 발급한 것처럼 표시하지 않습니다.
