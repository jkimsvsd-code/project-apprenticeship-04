# 과제 4 제출문 초안

**8A 초안 · 2026-10-26 KST · 아직 최종 제출하지 않았습니다.** 실제 운영 기록은 한 날짜분이며 플랫폼 봉인 영수증은 0건입니다. 고정 보관본·대조 화면은 구현했으며, 실제 이틀 영수증 검증과 최종 제출문 확정은 7B·8B에 진행합니다.

## 프로젝트 소개

서울 고정 대표 지점의 모델 기반 기온을 실제로 조회하고, 값·단위·출처·원천 시각·조회 시각·KST 일별 기록과 변화를 보여 주는 공개 정보판입니다. 외부 원천의 조회가 실패해도 마지막 정상값을 보존하고, 실패 5종과 복구는 실제 기록과 분리한 합성 패널에서 확인합니다.

## 주소

- 결과물 주소: [공개 정보판](https://project-apprenticeship-04.vercel.app/)
- 공개 소스 주소: [전체 소스 · commit 고정](https://github.com/jkimsvsd-code/project-apprenticeship-04/tree/3e919bed097659f4931e40dc6ffca2ea9aaecfc6)

각 필드에는 HTTPS URL 한 개만 기재했습니다. 소스 주소는 7A 완료 시점의 전체 40자리 commit에 고정한 초안 기준입니다. 8B에서 최종 제출 대상 commit으로 갱신하고 두 주소의 무인증 접근을 다시 확인합니다.

## 짧은 확인 방법 4줄

1. 어디로 가나요: 결과물 주소에서 상단의 실제 기온·일별 기록과 아래의 ‘데이터가 오지 않는다면?’ 합성 패널을 확인합니다. 로그인은 필요하지 않습니다.
2. 무엇을 하나요: 합성 패널에서 ① ‘정상 기준값 105 준비’ → ② 실패 한 종류 선택 → ③ ‘다시 시도 · 합성 D2 복구’를 누릅니다.
3. 무엇이 보이면 통과인가요: 실패 시 105pt·1건·오래된 값이 유지되고, 복구 시 120pt·2건·정상과 합성 계산 상세의 증가 15pt가 보이면 합성 확인 통과입니다. 실제 이틀 확인은 아래 미완료 항목입니다.
4. 안 될 때 무엇이 보이나요: 시간 초과·원천 접근 거절·호출 제한·연결 불가·형식 변경을 구분해 이유와 다음 행동을 표시합니다. 정상값이 있으면 보존하고, 없으면 값 없음을 안내하며 대기·재시도를 표시합니다.

합성 확인은 실패 종류별로 기준값 준비부터 반복합니다. ‘원천 401 거절’은 데이터 제공자 오류이며 방문자에게 로그인을 요구하는 기능이 아닙니다. 위 3단계는 실제 날씨 조회나 실제 이틀 기록을 생성하지 않습니다.

## AI와 나의 판단 3줄

1. AI에게 맡긴 일: 과제 요구사항과 공식 자산 분석, 원천·구현 방식 제안, 정보판과 합성 재생 구현, 시험·공개 보안 점검 및 제출문 초안 작성을 맡겼습니다.
2. 직접 판단한 일: 필수 1~8과 U1~U7을 우선 범위로 승인하고 U9는 후속 확장으로 두었으며, 공개 저장소를 직접 만들고 단계마다 커밋하도록 정했습니다.
3. AI 제안을 따르지 않은 일: 처음 제시된 진행 순서를 그대로 따르지 않고, 실제 이틀 검증을 마지막에 두며 공개 점검과 제출문 초안을 먼저 진행하는 순서로 바꾸도록 요청했습니다.

이 세 문장은 대화에서 확인된 요청·선택을 반영한 초안입니다. 최종 제출 전 학생 본인이 표현과 사실관계를 확인합니다.

## 실제 이틀 검증과 최종 확정에 남은 일

- [ ] 플랫폼의 공식 `t04_day` 영수증 발급 절차를 확인합니다. 공개 계약에 API나 발급 조작법이 없으므로 임의 절차를 만들지 않습니다.
- [ ] 서로 다른 실제 KST 날짜에 대응하는 봉인 영수증 정확히 2건을 확보합니다. 현재 일반 일별 기록 한 건을 영수증으로 바꾸어 세지 않습니다.
- [ ] 각 영수증의 `server_created_at`을 KST로 변환해 날짜가 다른지 확인하고, payload의 `source_url`, `source_observed_at`, `normalized_value`, `unit`을 앱에 보존한 같은 일별 저장값·원자료·화면값과 대조합니다.
- [x] 조회별 고정 보관본과 UUID 링크, 원자료·정규화 값·영수증 대조 항목 표시 및 두 고정 링크 비교를 구현했습니다. [이틀 확인 방법](preserved-readings.md)을 따릅니다. 공식 영수증과의 실제 일치는 아직 대조 전입니다.
- [ ] 두 영수증의 `server_created_at` 순서로 변화량을 다시 계산해 화면과 대조합니다. 합성 100/105/120pt·8월 날짜나 개발 DB 시험으로 대체하지 않습니다.
- [ ] 35개 공식 조건을 각각 최종 판정하고, 학생 판단 3줄 확인·최종 소스 commit URL 갱신·공개 접근 재확인 후 제출문을 확정합니다.

확인법·판단 기록은 C27·C28, 두 주소의 형식은 C34·C35에 대응하는 초안입니다. C22~C24의 실제 이틀·영수증 대조는 미완료이며, 이 문서는 플랫폼 제출·강사 승인·마스터 승인 또는 최종 채점 결과가 아닙니다. 학생이 별도의 봉인 파일이나 증거 ZIP을 직접 만들지 않습니다.
