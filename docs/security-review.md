# 7A 공개 접근·보안 점검

결과는 [7A 보고서](../evidence/implementation/stage7a.json), 자동 요청·스캔은 [상세 결과](../evidence/security/public-access-and-secret-scan.json)에 있습니다. 점검 시점의 제한된 범위이며 실제 이틀·플랫폼 영수증 검증이나 모든 공격에 대한 안전 보장을 뜻하지 않습니다.

## 공개 접근

결과물 HTTPS URL과 40자리 commit 고정 GitHub 소스 URL에 쿠키·Authorization 없이 요청해 200을 확인했습니다. HTTP는 HTTPS로 이동하고 읽기 API는 `no-store`입니다. 고정 commit의 원본 소스 파일을 로컬 Git blob과 대조했으며 같은 commit의 ZIP을 무인증으로 받을 수 있습니다.

사용자가 새 시크릿 창에서 두 주소 모두 계정 생성·로그인·인증·초대·비밀번호·OAuth·CAPTCHA 없이 내용을 확인했다고 이 대화에서 답했습니다. Chrome 자동 제어는 응답하지 않아, 이 항목을 자동 시크릿 창 시험으로 기록하지 않습니다. GitHub의 선택적 Sign in 링크는 소스 열람을 막는 절차와 구분합니다.

## 응답과 입력 보호

- 전 경로: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, 카메라·마이크·위치 권한 사용 금지.
- CSP: `frame-ancestors 'none'; base-uri 'self'; object-src 'none'; form-action 'self'`. 삽입·base·object·form 경로를 제한합니다. `script-src`를 제한하는 완전한 CSP라고 주장하지 않습니다. Next.js inline hydration은 허용된 기존 동작이며 적용 후 실제 조회·재생을 검증했습니다.
- Vercel HTTPS/HSTS와 프레임워크 버전 헤더 비노출을 확인했습니다.
- 다른/잘못된 Origin과 cross-site는 403, 임의 값·날짜·원천 URL 주입은 400, DELETE는 405입니다. 거절 응답은 내부 DB 오류나 비밀값을 담지 않으며 거절 전후 실제 읽기 응답이 같습니다.
- `.env`·환경별 비밀 파일·Git 설정·Vercel 로컬 설정 경로는 404입니다.
- 원천은 서버의 고정 Open-Meteo URL입니다. 공개 요청이 서버 원천 URL·조회 날짜·저장값을 지정하지 못합니다. 조회는 익명으로 허용하므로 Origin 검사는 인증이 아닙니다.
- 서버가 DB에 저장한 최소 15초 간격과 원천 Retry-After를 적용합니다. 실제 공개 조회 직후 다른 무인증 클라이언트 요청이 429로 차단됐습니다. 부하 시험이나 악의적 호출 전체를 막는다는 주장은 하지 않습니다.

## 비밀값·개인정보·의존성

현재 로컬 환경변수의 비밀값 원문·URL 비밀번호와 일반적인 개인키·GitHub 토큰·AWS 키·JWT·비밀번호 포함 DB URI 패턴을 대조합니다. 검사 대상은 저장소 후보 파일, 모든 로컬 ref에서 도달 가능한 Git blob과 커밋·트리·태그 메타데이터, 로컬 클라이언트/서버 빌드, 공개 HTML/API/JS/CSS 응답입니다. 값 자체는 출력·전송하지 않습니다.

서버 번들의 사용자명·비밀번호가 각각 온전한 JavaScript 보간식인 런타임 URI 조립 코드는 비밀값 리터럴과 구분합니다. 이 경우에도 먼저 적용하는 실제 로컬 비밀값 원문 검사는 생략하지 않습니다. `non_secret_dynamic_uri_templates`는 이 구분 횟수입니다.

알려진 로컬 비밀값과 위 패턴 이외의 모든 미지의 비밀을 탐지한다는 보장은 없습니다. 원격 서버 번들은 공개 다운로드되지 않으므로 로컬 소스·서버 빌드를 검사했습니다. 저장소 계정/커밋 noreply 식별자는 사용자가 공개하도록 정한 프로젝트 식별 정보입니다.

공개 데이터는 서울 고정 대표 지점의 모델 기온과 합성 fixture입니다. 방문자의 위치·개인 계정·개인 기록을 수집하지 않습니다. 증거 화면과 제출 대상 파일에도 개인 기록을 넣지 않았습니다. 공식 자산 원본/해시는 보존하며, 별도 프로젝트 라이선스는 아직 정하지 않았습니다.

npm 공식 검사에서 개발 의존성을 포함한 알려진 취약점 0건을 확인했습니다. 조회 시점의 공개 advisory 기준이며 미공개 취약점 부재를 뜻하지 않습니다. 운영 로그는 보고서의 제한된 30분 error/fatal 조회에서 반환 0건이었으며 원문 로그를 공개하지 않습니다.

## 재현

Node.js 24와 프로젝트 의존성 설치 후 실행합니다. Git commit이 원격 공개 저장소에 push되고 해당 코드가 배포된 상태여야 합니다.

```bash
npm run build
node scripts/audit-public-release.mjs
npm audit --json
```

스크립트는 이 프로젝트의 고정 공개 주소만 사용하고 실제 기온 POST 새로고침은 하지 않습니다. 잘못된 POST/DELETE 거절 시험만 포함하며 전후 실제 상태를 대조합니다. 정상 상태에서 종료 코드 0과 JSON 결과를 출력합니다. 배포 전 헤더 기준선만 보려면 `--baseline`을 사용하고 이를 최종 보호 헤더 통과로 해석하지 않습니다. 스캔에 사용할 `.env.local`·`.env.production.local`이 없으면 알려진 비밀값 대조 대신 일반 패턴만 검사합니다.

## 남은 작업

8A의 확인법 4줄·학생 판단 3줄·제출 주소 초안은 작성했습니다. 2026-10-27에는 7B의 실제 두 날짜 앱 값·원자료·화면·계산을 읽기 전용으로 대조하고 공개 주소 네 곳의 HTTP 200을 확인했습니다. [실제 자료](../evidence/real/README.md)를 참고하세요. 공식 영수증은 사용자 확인 기준 0건으로 발급·대조가 남아 있으며, 8B에서 최종 commit URL로 공개 접근을 재확인합니다. 아직 없는 영수증을 만들어 기록하지 않습니다. 이번 갱신은 전체 보안 점검 재실행이나 플랫폼의 35개 조건 최종 채점·제출·강사 승인이 아닙니다.
