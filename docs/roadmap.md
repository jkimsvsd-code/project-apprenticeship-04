# 구현 순서와 후속 확장

## 현재 단계

필수 1~8과 U1~U7의 범위가 승인되었으며 다음을 완료했습니다.

- 공개 저장소 연결과 폴더·문서 골격 커밋
- 공식 자산 18개 확보, 목록의 17개 파일 SHA-256·fixture 9개 canonical hash 확인
- 공개 계약 v2.0.0의 35개 조건 및 PDF와의 차이 정리
- Open-Meteo 서울 고정 지점 기온 선정과 실제 HTTP 200 사전 조회
- 참조 adapter의 정상·실패 5종·복구 상태 전이 검사

다음 단계는 프레임워크·영속 저장 방식을 정하고 실제 조회 → 정규화 → 저장 → 표시를 연결하는 것입니다. 앱·배포·실제 이틀 영수증 검증은 아직 미완료입니다. 사전 조회는 첫날 영수증으로 계산하지 않습니다.

## 구현 순서

1. [완료] 공식 자산 계약·해시·제공 조건을 확인하고 비개인 공개 데이터 원천 하나를 선택합니다. 명시적 재라이선스 권한은 추가하지 않습니다.
2. 프레임워크·공유 영속 저장·배포 방식을 정하고 조회 → 검증 → 저장 → 표시를 구현합니다.
3. 실제 첫날 기록을 가능한 이른 시점에 확보합니다.
4. 마지막 정상값·오류 5종·복구·KST 날짜별 저장·변화량을 구현하고 검증합니다.
5. U1~U7을 연결하고 실제 데이터와 합성 재생의 격리를 확인합니다.
6. 플랫폼 공식 절차를 확인하고 서로 다른 실제 KST 날짜의 t04_day 영수증 정확히 2건을 확보하여 저장값·화면값·계산 근거를 대조합니다.
7. 공개 URL·소스·비밀값·접근성을 확인하고 제출문을 완성합니다.

실제 날짜 경과가 필요한 6번은 작업시간과 별개입니다. 날짜가 바뀌지 않았다면 완료로 표시하지 않습니다.

## 후속 확장 U9

- 자동 갱신: 원천 호출 제한과 중복 실행 방지, 비활성 화면의 갱신 정책을 정한 뒤 추가합니다.
- 장기 추이 차트: 제출용 실제 이틀 기록과 장기 보관 정책을 정리하고 결측 날짜와 오래된 값을 구분해 표시합니다.

U8 검증 결과 복사·다운로드는 현재 미승인입니다. 후속 구현 대상으로 자동 편입하지 않습니다.
