# 구현 순서와 후속 확장

## 현재 단계

필수 1~8과 U1~U7의 범위가 승인되었으며 다음을 완료했습니다.

- 공개 저장소 연결과 폴더·문서 골격 커밋
- 공식 자산 18개 확보, 목록의 17개 파일 SHA-256·fixture 9개 canonical hash 확인
- 공개 계약 v2.0.0의 35개 조건 및 PDF와의 차이 정리
- Open-Meteo 서울 고정 지점 기온 선정과 실제 HTTP 200 사전 조회
- 참조 adapter의 정상·실패 5종·복구 상태 전이 검사
- 기술 스택: Next.js App Router·TypeScript·Node.js 24, npm
- 영속 저장과 배포: Neon Postgres·Vercel, 서버 전용 DB 접근과 합성 상태 격리 설계

2026-10-27 KST 현재 8A 초안과 고정 보관 기능에 이어 **7B의 실제 두 날짜 앱 기록 대조**를 완료했습니다. 운영의 10월 26일 14.6°C·27일 12.8°C의 원자료·저장값·고정 화면과 **1.8°C 감소**가 일치합니다. [실제 검증 자료](../evidence/real/README.md)를 추가하고 [제출문 초안](submission.md)을 보완했습니다. 앞 단계의 실제 연결·DB 격리·합성 실패/복구·UX·공개 접근/보안 검증은 완료 상태입니다. 이후 로그인한 공식 화면에서도 과정 기록 0건과 입력 경로를 확인했습니다. 현재 웹의 선택 기록 안내·C22~C24 문구가 보관된 공개 계약과 달라 [차이를 기록](official-receipt-check.md)했습니다. 영수증 payload 대조는 원문이 없어 미실시입니다. 영수증 발급을 제출·승인의 필수 선행 단계로 안내하지 않으며 8B 최종 문서는 아직 확정하지 않았습니다.

## 구현 순서

| 단계 | 작업 | 상태 |
| --- | --- | --- |
| 1 | 목표·기능 범위·폴더 구조 정리, 공개 소스 연결 | 완료 |
| 2 | 공식 검사 자산 검증·데이터 원천 선정 | 완료 |
| 3 | 기술 스택·영속 저장 방식 결정 | 완료 |
| 4 | 실제 조회 → 정규화 → 영속 저장 → 기본 화면 구현 | 완료 |
| 5 | 실패 5종·정상값 보존·합성 복구 구현 | 완료 |
| 6 | KST 일별 기록·변화량과 UX U1~U7 구현·검증 | 완료; 실제 두 날짜 대조는 별도 |
| 7A | 공개 배포·무로그인 접근·공개 소스·비밀값 종합 점검 | 완료; 자동 HTTP/브라우저 및 사용자 시크릿 창 확인 |
| 8A | 확인법 4줄·판단 3줄·제출 문서 초안 | 완료; 최종 제출·학생 문구 확정은 8B |
| 7B | 서로 다른 실제 이틀 기록 및 플랫폼 영수증 대조 | 앱 값 대조·공식 경로/0건 확인 완료. 영수증 payload는 미실시, 웹·공개 계약 차이 기록 |
| 8B | 검증 결과 반영·최종 commit 고정 소스 URL·제출문 확정 | 다음; 기준 차이와 영수증 미실시를 명시하고 확정 |

연결 재현은 [실제 연결 준비](setup.md), 합성 재생은 [재생 안내](simulation.md)를 따릅니다. 6단계에서 실제 기록의 비교 날짜·계산 상세, 경과 시간, 대기 안내와 모바일·키보드 기본 조작을 구현·검증했습니다. 계산 엔진은 단위 변화·비연속 날짜·증가/감소/변화 없음·음수/0을 검사했습니다. 합성 시험과 구별하여 이번에는 실제 운영의 서로 다른 두 KST 날짜를 확인했습니다. 봉인 영수증은 사용자 확인 기준 0건이며, 앱 기록 두 날짜를 봉인 증거 두 날짜로 대신하지 않습니다.

보관된 공개 계약의 영수증 기반 판정까지 검증하려면 서로 다른 실제 KST 서버 날짜의 t04_day 원문 2건이 필요합니다. 현재 웹은 과정 기록이 없어도 제출·승인을 막지 않는다고 명시하므로 영수증 발급을 강제하지 않습니다. 서버 작성 날짜를 과거 앱 조회 날짜로 대신하지 않고, 영수증 없이 payload·봉인 검증을 통과로 표시하지 않습니다.

각 단계는 검증 → 커밋 → push → 결과 공유 순서로 완료합니다. 한 번에 다음 한 단계씩 진행합니다.

## 후속 확장 U9

- 자동 갱신: 원천 호출 제한과 중복 실행 방지, 비활성 화면의 갱신 정책을 정한 뒤 추가합니다.
- 장기 추이 차트: 제출용 실제 이틀 기록과 장기 보관 정책을 정리하고 결측 날짜와 오래된 값을 구분해 표시합니다.

U8 검증 결과 복사·다운로드는 현재 미승인입니다. 후속 구현 대상으로 자동 편입하지 않습니다.
