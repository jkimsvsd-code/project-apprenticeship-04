# 구현 순서와 후속 확장

## 현재 단계

필수 1~8과 U1~U7의 범위가 승인되었으며 다음을 완료했습니다.

- 공개 저장소 연결과 폴더·문서 골격 커밋
- 공식 자산 18개 확보, 목록의 17개 파일 SHA-256·fixture 9개 canonical hash 확인
- 공개 계약 v2.0.0의 35개 조건 및 PDF와의 차이 정리
- Open-Meteo 서울 고정 지점 기온 선정과 실제 HTTP 200 사전 조회
- 참조 adapter의 정상·실패 5종·복구 상태 전이 검사
- 기술 스택: Next.js App Router·TypeScript·Node.js 24, npm
- 영속 저장과 배포: Neon Postgres·Vercel, 서버 전용 DB 접근과 합성 상태 격리 설계

현재는 5단계 공식 실패·복구 재생까지 완료했습니다. Vercel·Neon 실제 연결, 개발/운영 DB 분리, 앱 역할 권한 분리, 초기 migration, 로컬 화면의 실제 조회·저장·재접속을 확인했습니다. 공식 fixture 9개의 상태 전이를 참조 adapter와 대조했고 브라우저의 실패 5종·복구·동일 날짜 갱신·초기화 및 실제 기록 불변을 확인했습니다. 다음은 6단계의 실제 일별 비교·변화량 UI와 남은 UX 구현입니다. 최종 공개 점검·실제 이틀 영수증 검증은 아직 미완료입니다. 개발 DB 시험을 제출용 영수증으로 계산하지 않습니다.

## 구현 순서

| 단계 | 작업 | 상태 |
| --- | --- | --- |
| 1 | 목표·기능 범위·폴더 구조 정리, 공개 소스 연결 | 완료 |
| 2 | 공식 검사 자산 검증·데이터 원천 선정 | 완료 |
| 3 | 기술 스택·영속 저장 방식 결정 | 완료 |
| 4 | 실제 조회 → 정규화 → 영속 저장 → 기본 화면 구현 | 완료 |
| 5 | 실패 5종·정상값 보존·합성 복구 구현 | 완료 |
| 6 | KST 일별 기록·변화량과 UX U1~U7 구현·검증 | 예정 |
| 7 | 공개 배포·실제 이틀 기록 및 플랫폼 영수증 검증 | 예정 |
| 8 | 최종 공개 점검·제출 문서 완성 | 예정 |

연결 재현은 [실제 연결 준비](setup.md), 합성 재생은 [재생 안내](simulation.md)를 따릅니다. 6단계에서 실제 기록의 비교 날짜·계산 상세, 경과 시간, 대기 안내와 모바일·키보드 접근성을 완성합니다. U1~U7 전체를 완료한 것으로 표시하지 않습니다. 실제 첫날 조회는 확보했으며 플랫폼 영수증 발급 절차는 별도 확인이 필요합니다.

7단계에서는 공식 절차로 서로 다른 실제 KST 날짜의 t04_day 영수증 정확히 2건을 확보해 저장값·화면값·계산 근거를 대조합니다. 실제 날짜 경과는 작업시간과 별개입니다. 날짜가 바뀌지 않았다면 완료로 표시하지 않습니다.

각 단계는 검증 → 커밋 → push → 결과 공유 순서로 완료합니다. 한 번에 다음 한 단계씩 진행합니다.

## 후속 확장 U9

- 자동 갱신: 원천 호출 제한과 중복 실행 방지, 비활성 화면의 갱신 정책을 정한 뒤 추가합니다.
- 장기 추이 차트: 제출용 실제 이틀 기록과 장기 보관 정책을 정리하고 결측 날짜와 오래된 값을 구분해 표시합니다.

U8 검증 결과 복사·다운로드는 현재 미승인입니다. 후속 구현 대상으로 자동 편입하지 않습니다.
