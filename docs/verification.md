# 검증 계획

공식 자산·참조 adapter, 실제 조회·저장에 더해 5단계 합성 재생을 확인했습니다. [5단계 검증](../evidence/implementation/stage5.json)은 단위 42개·개발 DB 통합 4개, 앱 상태와 참조 adapter의 전체 상태 비교, 실제 브라우저의 실패 5종·복구·초기화·실제 기록 불변을 다룹니다. [4단계 검증](../evidence/implementation/stage4.json)은 기본 조회·저장·재접속 자료입니다. 실제 변화량 UI·남은 UX·최종 공개·실제 이틀 검증은 아직 미완료입니다. [공식 자산 보고서](../evidence/synthetic/asset-verification.json)는 제품 판정과 구분합니다.

## 공식 자산 확인

1. 과제 PDF의 README·public-contract.json·asset-manifest.json·ZIP을 확보합니다.
2. manifest의 적용 범위를 확인하고 대상 파일의 SHA-256을 대조합니다.
3. package ID·버전·검증 일시·대상 파일·기대 해시·실제 해시·일치 여부를 `evidence/synthetic/`에 남깁니다.
4. 원본은 `public/task-assets/t04/`에 보관하고 자산을 수정하여 검사 결과를 맞추지 않습니다.

확보된 계약은 v2.0.0이며 35개 조건을 요구합니다. 재검증 명령은 `node scripts/verify-task-assets.mjs`입니다. 원본 17개 파일 해시·fixture 9개 canonical hash·참조 정상 1개/실패 5개/복구 5개 시퀀스를 검사합니다. 이 검사는 앱이 아닌 공식 자산과 참조 코드에만 적용됩니다.

## 합성 재생 시나리오

- 공식 계약대로 합성 상태를 초기화합니다.
- D1-A 성공 후 D1-B 성공: 값의 갱신과 같은 날 기록 한 건을 확인합니다.
- 각 실패를 독립적으로 재생: 실패 종류·이유·다음 행동이 다르고, 마지막 정상값은 남아 있으며 오래된 값 표시가 붙는지 확인합니다.
- 각 실패에서 지정 복구를 재생: `fresh`, `error_code: none`으로 돌아오고 다음 날짜 기록이 정확히 한 건 추가되는지 확인합니다.
- 같은 날짜 세 번 성공·다음 날짜 한 번 성공을 합성 시계로 확인합니다.
- 데이터가 없는 초기 실패, 중복 클릭, 재시도 대기, 시험 초기화가 실제 기록을 건드리지 않는지도 확인합니다.

세부 조작과 fixture 매핑은 [합성 재생 안내](simulation.md)를 따릅니다. 앱 재생 시험은 fixture의 `expected`를 입력에서 제거하거나 변조해도 결과가 동일한지 확인하며, 실제 상태를 공식 참조 adapter와 대조합니다. 세부 fixture·입력 필드·오류 코드는 [확보한 계약](task-contract.md)에 따라 연결합니다. 원본 수정 시 검증 스크립트가 실패하는지도 임시 사본에서 확인합니다.

## 실제 이틀 검증

1. 실제 첫날: 공개 원천 조회 성공 후 URL·관측 시각·조회 시각·KST 날짜·값·단위와 원자료를 보존합니다.
2. 다른 실제 KST 날짜: 같은 원천을 조회하여 두 번째 일별 기록을 확보합니다.
3. 두 기록 각각의 원자료·저장값·화면값을 대조하고 같은 계산 규칙으로 변화량을 재계산합니다.
4. 플랫폼의 공식 절차로 봉인된 canonical kind `t04_day` 영수증을 정확히 2건 확보하고 각 `server_created_at`의 KST 날짜가 다른지 확인합니다. 발급 절차는 공개 계약에 없으므로 별도로 확인해야 합니다.
5. 각 영수증 payload의 `source_url`, `source_observed_at`, `normalized_value`, `unit`을 앱의 같은 일별값·화면값과 대조합니다. `server_created_at` 시간순으로 변화량을 재계산합니다. 학생이 별도의 인증 파일이나 증거 ZIP을 직접 만들 필요는 없습니다.

합성 날짜·과거 원천 데이터·시계 조작으로 실제 조회 이틀을 대체하지 않습니다. 두 날짜가 연속되지 않으면 실제 비교 날짜를 표시합니다.

## 공개 전 확인

- 새 시크릿 창에서 결과물과 소스를 열어 로그인·계정 생성·비밀번호·OAuth·CAPTCHA·초대가 없는지 확인합니다.
- 브라우저 코드·배포 산출물·네트워크 응답·저장소 및 Git 기록의 비밀값 노출 여부를 확인합니다. `.gitignore`는 이미 노출된 값이나 기존 Git 기록을 정리하지 않습니다.
- 증거·화면·제출 파일에 실제 개인정보·개인 기록이 없고 실패 재생이 합성 값만 사용하는지 확인합니다.
- 공식 자산의 재배포 조건과 저장소 라이선스를 확인합니다.
- 실제 배포 환경에서 저장 기록이 재시작·다른 브라우저 접속 후에도 유지되는지 확인합니다.
- 제출문의 4줄 확인법과 3줄 판단 기록을 완성합니다.
- C01~C35를 각각 판정합니다. C34의 HTTPS 결과물 URL 한 개, C35의 전체 commit ID를 포함한 HTTPS 소스 URL 한 개를 확인합니다.
